# 자동 발행 글 작성 규칙

## 구조 (1,200~2,000자)

```
---  (프런트매터: assets/post_template.md)
## 첫 섹션 = 답           검색자가 찾는 답을 2~4문장으로. "결론부터 말하면 …"
## 왜 그런가               근거 — 축 데이터의 사실(검색 방식·결정 기준·성수기·지표)
## 확인할 것 / 하는 법      불릿 3~6개. 실행 가능한 단위로
## 흔히 놓치는 것          1~2개, 짧게
## 다음 단계               도구 링크 + 관련 고정 페이지 2개 + (해당되면) 견적/문의 링크
```

제목은 **키워드 그대로 + 질문/의도 어휘**: `치과 블로그 마케팅 비용, 월 얼마가 적정할까요`. 키워드를 앞에, 설명은 뒤에.
description은 답을 한 문장으로 요약 (SERP 스니펫이 곧 답이 되게).

## 패턴별 섹션 틀

| pattern | 첫 섹션(답) | 근거 재료 |
|---|---|---|
| cost (비용) | 범위 + 범위가 갈리는 이유 | channel.costRange, 작업 범위 항목 |
| agency (업체 고르는 법) | 확인 질문 3개 | channel.pitfalls, metrics |
| diy (직접 하는 법) | 첫 주에 할 3가지 | channel.steps + 업종 사례 |
| mistake (흔한 실수) | 가장 흔한 실수 1개와 결과 | pitfalls, howItRanks |
| local-cost / local-agency (지역) | 지역 특성 한 줄 + 답 | region.aliases, 업종 searchPattern |

## 톤

- 사장님에게 설명하는 담당자 말투. 존댓말, 짧은 문장, 전문용어는 한 번 풀어쓴다.
- "~할 수 있습니다"보다 "~하세요 / ~부터 확인하세요" — 행동 지시형.
- 과장·감탄·이모지 없음. "획기적", "완벽" 금지.

## 금지

- 출처 없는 수치·통계 ("평균 30% 상승") — 데이터의 범위값만. 없으면 "업체·범위에 따라 다릅니다"로 둔다.
- 다른 글의 문단 복사. 같은 패턴이라도 업종 사실로 문장을 다시 쓴다.
- 키워드 반복 채우기 — 제목·첫 문단·마지막에 각 1회면 충분.
- 외부 경쟁사 언급, 특정 업체 비방.
- 결제·보장 표현("상위노출 보장").

## 내부링크 (3개 이상, 본문 안에 자연스럽게)

- 업종 허브 `/guide/{업종}-마케팅`, 채널 허브 `/guide/{채널}-마케팅-가이드`
- 해당 채널 도구 (`channel.rankTool`, `channel.diagTool`)
- 전환 페이지 1개 (견적비교 등) — 마지막 섹션에만

## 자기 점검 (저장 전)

- [ ] 첫 섹션만 읽어도 답이 되는가
- [ ] 숫자마다 근거(데이터 필드)가 있는가
- [ ] 내부링크 3개 이상, 모두 실제 존재하는 경로인가
- [ ] 1,200~2,000자인가
- [ ] 프런트매터 slug·keyword·publishedAt 채웠는가, slug가 큐의 다른 글과 안 겹치는가

---

## 이 사이트(파워크레인) 적용 — 위 일반 규칙보다 우선

- 글 위치 `content/blog/<slug>.md`, 형식·톤은 `content/blog/_example.md` 를 따른다. 프런트매터 `industry` 는 큐 값(공통·카고크레인·하이드로크레인·스카이차), `channel`·`region` 은 null.
- 패턴(pattern): choose(장비·톤수 선택) · radius(반경·높이·제원) · permit(허가·통제) · safety(안전) · prep(현장 준비) · compare(장비 차이) · job(작업별 방법). 첫 섹션은 그 질문의 답 2~4문장.
- 근거: `SITE.md`, `data/fleet.json`(보유 장비 — 이 목록에 없는 장비를 보유했다고 쓰지 않는다. 미니크레인·사다리차는 "배차 가능 여부 상담"), `data/equipment.json`·`tons.json`·`uses.json`.
- **가격·소요 시간 숫자 쓰지 않는다.** 법규 수치·통계도 데이터에 없으면 쓰지 않는다("현장·관할에 따라 다릅니다").
- 내부링크 3개 이상: `/<slug>/` 형식, `data/site-pages.json` 에서 `wave <= WAVE` 인 slug 만. `/area/`, `/blog/` 도 가능. 마지막 섹션은 상담(현장 사진 문자) 안내.
- 지역+서비스 주제("고양 크레인")로 쓰지 않는다 — 지역 페이지와 겹친다. 지역 페이지는 링크로만 연결.
- 검증: `python3 scripts/drip/validate_posts.py content/blog --slugs <…> --queue content/blog/_data/keywordQueue.json`
- 예약 공개: 프런트매터 `date: YYYY-MM-DD`(KST)가 빌드일(env `BUILD_DATE` 또는 KST 오늘)보다 미래인 글은 목록·글·sitemap·rss·og 에서 빠진다(`lib/blog.ts`). `publishedAt` 도 같은 날짜로 채운다(검증 스크립트 필수 항목).
- 미리 써 두는 글의 내부링크는 wave 1 slug(항상 열려 있음)와 `/area/`·`/blog/` 위주로. 다른 블로그 글(`/blog/<slug>/`)로 걸면 그 글이 아직 공개 전인 날엔 링크 없이 글자만 보이므로 3개 개수에 넣지 않는다.
